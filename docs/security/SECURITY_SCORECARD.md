## Environment sensitivity

Two dimensions are **environment-specific and fully remediable** — they are low in
the zero-config development profile by design, and the scanner correctly flags
them:

1. **Secrets (20 → ~100)** — the development profile ships placeholder secrets
   (`SECRET_KEY`, `JWT_SECRET_KEY`, …). `settings.validate_runtime()` and the
   secret scanner flag these as **critical**. Setting strong random secrets in
   staging/production (as `deploy/env/production.env.example` documents) raises
   this dimension to ~100. This is a **feature**: the platform refuses to silently
   pass a deployment that uses default secrets.
2. **Supply chain (60)** — `requirements.txt` pins no Python versions (27
   production dependencies). This is an **accurate, honest finding**; pinning
   versions and committing a lockfile remediates it.

With these two items addressed, the overall posture reaches the **B+/A- band**.
